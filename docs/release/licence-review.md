# Licence review record

Task T-REL-02, risk R13, decisions D4, D5 and D7. This is the engineering record for the legal review: what
BDK ships, under which terms, what was checked, and the questions only counsel can answer. It is not legal
advice and it is not the review itself. **The legal review has not taken place**; each item marked "Counsel" is
open until it has.

Written 2026-11-25 against Chromium `158.0.8127.37` and the repository at that date.

## 1. What a BDK release ships

| Artifact | Contents | Notices |
|---|---|---|
| Runtime (`runtimes/<key>`, the published archive, and the framework an application embeds) | Chromium built from source with BDK's patches and `//bdk` overlay | Chromium's credits page: `chrome://credits` inside the framework, and `THIRD_PARTY_NOTICES.html` at the top of the runtime (section 3) |
| `bdk` executable | BDK's CLI bundled with `ajv`, `smol-toml` and their dependencies, inside a Node 26 single executable | `THIRD_PARTY_NOTICES.txt` in the artifact bundle, generated by `tooling/src/release/notices.ts --node` (section 3) |
| Swift package | BDK's Swift and C sources | BDK's own licence only |
| `@bdk/*` packages | BDK's TypeScript, no runtime dependencies | BDK's own licence only |
| Example applications | BDK's code; they embed the runtime | the runtime's notices, copied by the application (section 3) |

## 2. Findings

| # | Item | Finding | Status |
|---|---|---|---|
| L1 | **BDK's own licence** | The repository has no `LICENSE` file and no `license` field in any `package.json`. Nothing BDK wrote can be redistributed by anyone else until one is chosen. Chromium's BSD-3-Clause and the licences of what it bundles constrain notices, not the choice. | **Blocker for public v1.** Product owner to choose; then add `LICENSE`, the `license` fields and an SPDX header policy. |
| L2 | Chromium and its third-party code | Chromium is BSD-3-Clause; `third_party/` carries many licences, including LGPL (for example FFmpeg's LGPL parts, built as part of the framework) and MPL-2.0 components. Chromium's own tooling (`tools/licenses/licenses.py credits`) produces the credits page from each directory's `README.chromium`. A non-official build copies a placeholder instead unless `generate_about_credits = true`. | Fixed: both GN presets set it, and packaging refuses the placeholder. The LGPL obligations of a statically linked framework (relinking, source offer) — Counsel. |
| L3 | Scope of the credits | `licenses.py credits` scans the checkout's third-party directories for the target OS, not the exact dependency graph of the BDK build, so the notices may list more than is linked. Over-inclusion is the safe direction. | Accepted; Counsel to confirm. |
| L4 | `bdk` executable | Its bundled npm packages are MIT or BSD-3-Clause today (`ajv`, `fast-deep-equal`, `json-schema-traverse`, `require-from-string`: MIT; `fast-uri`, `smol-toml`: BSD-3-Clause); the executable also embeds Node, whose `LICENSE` covers Node and its bundled libraries (V8, OpenSSL, ICU, libuv and others). `notices.ts` fails on any licence outside the accepted list in section 4 or a package with no licence text; a test runs it against `packages/cli` on every `tooling:test`. | Done for generation; copying it into the artifact bundle is a release step ([procedure.md](procedure.md) 2.4). |
| L5 | **D4, Chrome Web Store** | Off by default; an application enables it as a named source after its own legal review. Google's store terms describe distribution to Chrome users and have no clause for other browsers. The "Add to <browser name>" relabel changes Google's page at run time. BDK does not enable the store for any application and ships no store credentials. | Recorded. Counsel: whether BDK may document the source at all, and whether the relabel is acceptable to Google. Each application's own review is required by design. |
| L6 | **D5, security component data** | The component updater is off; nothing is downloaded from Google. What ships is what Chromium compiles in: the Certificate Transparency log list and the Chrome Root Store (from Chromium's source tree, under Chromium's licence and the data's own terms), and an empty CRLSet. No Google-signed component package is redistributed. | Recorded. Counsel: the terms of the Chrome Root Store and CT log list data as redistributed in a non-Google product. |
| L7 | **D7, codecs** | The runtime has `proprietary_codecs = false` and `ffmpeg_branding = "Chromium"` (measured, feasibility 7.1): no H.264, AAC or HEVC decoder is in the runtime, and pages are offered VP9, AV1 and Opus only. The decided direction is to decode H.264, AAC and HEVC through macOS's own decoders (VideoToolbox, AudioToolbox), which needs `proprietary_codecs = true` with Chromium branding and a patch for AAC-LC (T-CHR-12, not built). Turning on `proprietary_codecs` also compiles in MP4 demuxing and the codec strings. | Not built. Counsel, before that build ships: whether demuxing and handing H.264, AAC or HEVC to the operating system's licensed decoders needs a patent-pool licence for BDK or for each application. Until then the runtime ships open codecs only. |
| L8 | **Widevine** | Not in v1 (product owner, 2026-11-25). Nothing of it is built or shipped; with the component updater off no CDM is ever downloaded. | Closed for v1. A later opt-in needs Google's Widevine licence per application. |
| L9 | Trademarks | Framework and helper names are neutral ("Chromium Framework", "Chromium Helper"); `bdk.toml` names the product. Built-in pages still show the Chromium logo until branding (S13) substitutes the application's. "Chromium" and its logo are Google trademarks under Chromium's branding guidelines. | Counsel: whether the Chromium name in the framework's file names and the logo in built-in pages are acceptable in a third-party product. S13 removes the logo. |
| L10 | Reputation block lists (D2) | The default provider reads signed lists in BDK's own format; which open feeds fill them, and their licences, is not decided. | Open: each feed's licence must allow redistribution before a list is published (T-PRV follow-up). |
| L11 | Translation models | Where default on-device models are downloaded from is not decided (sdk/README.md section 7); their licences follow that choice. | Open, with that decision. |

## 3. How notices are produced and shipped

- **Runtime.** `chromium/gn/release.gn` and `dev.gn` set `generate_about_credits = true`, so the build runs
  `tools/licenses/licenses.py credits` into `out/<config>/gen/components/resources/about_credits.html`
  (declared in `components/resources/BUILD.gn` at the pin). The same file is compiled into
  `components_resources.pak`, which is `chrome://credits` (a route an application cannot disable,
  `packages/core/runtime/routes.cc`). `chromium/runtime-files.json` declares it under `notices`, so
  `chromium:package` copies it to `THIRD_PARTY_NOTICES.html` at the top of the runtime, lists it in the
  manifest, fails when the build did not write it, and refuses Chromium's placeholder. The dry run fails a
  published runtime without it.
- **Applications.** An application that embeds the framework must ship the notices too. `bdk build sign` does
  not copy `THIRD_PARTY_NOTICES.html` into the application yet (T-REL-02); until it does, the application
  copies it into its `Contents/Resources`.
- **`bdk` executable.** `pnpm exec tsx tooling/src/release/notices.ts --package packages/cli --node --out <file>`
  writes the production dependency closure of the CLI and Node's licence.

Not verified: a build with `generate_about_credits = true` (no build was run for this change). Its first run
will show whether `licenses.py` accepts every directory of the checkout; it fails on a shipped directory with no
licence file, which would then need an entry in `extra_third_party_notice_dirs` or a fix upstream.

## 4. Licences accepted without a separate review

For npm packages BDK bundles: `0BSD`, `Apache-2.0`, `BlueOak-1.0.0`, `BSD-2-Clause`, `BSD-3-Clause`, `CC0-1.0`,
`ISC`, `MIT`, `Unlicense`, and SPDX `OR` expressions with one of them. Anything else, including `MPL-2.0`, any
GPL or LGPL, and `WITH` exceptions, needs an entry in section 2 first. The list is `ACCEPTED_LICENCES` in
`tooling/src/release/notices.ts`.
